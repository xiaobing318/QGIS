# Processing 作业与覆盖确认

Vector、Raster 和 General 服务共用 QCopilots Common 的作业管理器。每个服务仍提供算法列表、算法详情、启动、查询、作业列表和取消六个 MCP 工具。本文说明客户端调用契约，不代表某个算法或运行环境已经通过验收。

## 启动、预览和执行

`start_<category>_processing_algorithm` 中的 `<category>` 为 `vector`、`raster` 或 `general`。调用返回作业快照和 `job_id`，客户端通过对应的 `get_<category>_processing_job` 查询后续状态。覆盖预览也采用此流程，不能再假定启动响应立即包含确认信息。

| `overwrite_outputs` | `overwrite_confirmation_token` | 行为 |
| --- | --- | --- |
| `false` 或省略 | 不提供 | 创建 `execute` 作业，预检通过后执行 |
| `true` | 不提供 | 创建 `preview` 作业，只预览，不运行算法 |
| `true` | 提供 | 创建 `execute` 作业，认领批准并复核后执行 |
| `false` 或省略 | 提供 | 拒绝不合法的参数组合 |

预览完成后，`confirmation_required` 等预览字段同时出现在快照顶层和 `result` 中。

- 有覆盖目标时，客户端取得确认信息，经批准后将返回的确认值传给新的执行请求。算法、参数和加载选项应与预览一致。
- 没有覆盖目标时，预览返回 `confirmation_required=false`，也不会运行算法。随后以 `overwrite_outputs=false` 发起执行。如果目标在两次调用之间出现，执行会拒绝覆盖。
- 预览失败时不继续执行。不要用重复调用或更改参数绕过失败原因。

## 状态和进度字段

公共状态保持为 `queued`、`running`、`cancelling`、`succeeded`、`failed` 和 `cancelled`。后三种是终态，但终态与文件清理完成是两个不同事实。

| 字段 | 含义 |
| --- | --- |
| `operation` | `preview` 或 `execute`，区分预览作业和执行作业 |
| `phase` | `preflight`、`execute`、`verify_outputs`、`publish`、`load_outputs`、`cleanup` 或 `complete` |
| `algorithm_executed` | 是否已经进入算法执行，不以作业是否为 `succeeded` 推断 |
| `progress_percent` | 算法进度，算法到达 100% 后仍可能继续校验、发布或清理 |
| `phase_progress` | 文件校验时的 `bytes_completed` 和 `bytes_total`，非文件阶段可为空 |
| `cancellable` | 当前阶段是否接受用户取消，客户端应读取最新值 |

文件字节计数描述当前文件校验的读取工作量。完整一致性复核读取两遍，因此总字节数可以为文件大小的两倍，处理下一个文件时可以重置。它不是整个作业的预计剩余时间。短阶段可能在相邻两次查询之间结束，客户端不应要求每次运行都观察到所有阶段。

`operation=preview` 且 `state=succeeded` 只表示预览已完成，`algorithm_executed` 应为 `false`。真正的执行结果必须检查 `operation=execute`、终态、`result` 和 `cleanup`。

## 请求幂等与确认期限

提供 `client_request_id` 后，预览和执行分别使用内部幂等命名空间。同一个标识可以先用于预览，再用于执行。在记录保留期间，各操作的相同请求重放返回对应的原作业，不再启动第二次操作。相同操作复用标识却改变请求内容会被拒绝。Binary 等其他作业管理器保持原默认命名空间。

确认信息绑定服务类别、算法、参数、项目加载选项、输入版本和覆盖目标版本。签发后默认有 300 秒提交期限，响应包含 `confirmation_expires_in_seconds` 和 UTC 的 `confirmation_expires_at`。期限从预览计算完成并签发确认值时开始，不从启动预览时开始。

执行请求成功认领后，批准快照归该执行作业持有。后台大文件复核超过原提交期限不会再次触发过期错误，但输入或目标发生变化仍会拒绝执行。一个确认值只能被一个新的执行请求认领。取消、失败或参数不匹配不会恢复该确认值。

执行请求的幂等重放先返回已有作业，不再次认领确认值。相同预览标识重放仍返回原预览，不自动延长期限。确认过期后使用新的 `client_request_id` 重新预览。

## 大文件与输入保护

普通本地文件的输入预检、覆盖预览、批准复核、输出校验和恢复校验在后台执行。使用分块 SHA-256，并检查读取前后的文件身份和元数据。为识别文件时间戳尚未更新的改写，完整读取两遍并要求摘要一致，每遍都支持分块取消。后台普通文件校验不再受原有 512 MiB 文件大小和 2 秒同步校验限制。该能力包括生成大文件后再次将其作为输入或覆盖目标，不是仅支持首次写出。

一致性复核增加文件读取量，不提供文件系统原子快照或外部写入锁。调用方仍应避免在处理期间持续修改输入和覆盖目标。

算法准备、工程图层和 QGIS 上下文操作仍由主线程管理。后台文件任务不替代上游算法的线程约定，也不会使所有算法都支持取消。

任务完成后，下一阶段通过主线程事件队列继续，待当前 QGIS 任务管理器完成回调和清理后再注册后续任务。等待续作期间仍保留作业资源，取消、关闭和历史淘汰规则也将其视为尚未完成的工作。

其他边界保持有效，包括输入数量、目录清单、非文件图层指纹及文件夹输出策略。当前目录清单最多 10,000 个条目和 512 MiB 内容，非文件图层指纹最多 50,000 个要素和 128 MiB 内容，并保留相应时间预算。不可因普通文件支持大数据而推断这些限制也已取消。

任务运行后的输入复核允许一种受限例外：GDAL PAM `.aux.xml` 中纯统计缓存的新增或更新。允许的字段为 `STATISTICS_MINIMUM`、`STATISTICS_MAXIMUM`、`STATISTICS_MEAN`、`STATISTICS_STDDEV` 和 `STATISTICS_VALID_PERCENT`。

接受此例外要求主栅格强版本不变，波段和数值有效，其他 XML 语义不变。CRS、NoData、GeoTransform、色表、掩膜、概览和 world file 不在例外内。已有统计字段的删除也不视为允许的增改。解析采用大小、节点数和深度限制，无法安全识别时按原有精确版本保护处理。

该例外只用于运行后的输入复核。覆盖确认仍精确绑定预览时的输入和目标版本。接受的缓存变化通过 `input_cache_changes` 返回路径、波段和字段名，说明的是允许的变化，不是对统计数值真实性的独立认证。

## 取消、发布与清理

输出先写入本作业暂存位置，全部输出预检通过后才发布。发布回执在目标变化前建立，逐步记录备份和已发布文件，失败时据此恢复。无法证明仍属于本作业版本的文件会保留，不因取消请求而强制删除。

取消是请求，不是立即完成的承诺。预检和输出校验可在分块边界响应取消。发布已开始时需要恢复原目标，恢复阶段不接受用同一个取消信号跳过必要清理。

客户端在终态后仍应检查 `cleanup.complete`、`residual_paths`、`errors` 和 `retry_recommended`。`cleanup.complete=false` 表示存在残留或尚不能验证恢复完成。后续 `get_job` 可以调度恢复重试并立即返回最新快照，不等待大文件校验结束。恢复证据更新不会将终态重新改成运行态。

清理未完成或任务仍持有资源时，完整恢复回执、作业记录和幂等关联不会因历史数量或默认 24 小时保留期限而被淘汰。恢复成功后可查询更新后的清理回执，正常保留期限重新起算，并重新受历史数量限制约束。

为限制保留资源的数量，每个 Processing 类别默认最多容纳 200 个活动或待恢复作业。预览和执行共用该类别的名额，尚未释放任务所有权的终态也占用名额。达到上限时，新请求返回 `processing_recovery_capacity_exceeded`，不会消耗确认值。已有作业的查询、恢复、取消和幂等重放仍可进行。清理完成并释放任务后，名额可供新作业使用。各类别分别计数，Binary 的历史保留行为不受此规则影响。

关闭采用有界等待。文件任务仍活动时不提前释放其资源或删除相关文件，无法确认清理时保留回执和残留信息。管理器内部关闭回执通过 `complete` 和 `pending_job_ids` 表达尚未结束的任务，相关作业快照的 `cleanup.complete` 标为 `false`。这不是新的 MCP 工具。本机制不承诺强制终止进程或断电后的自动事务恢复。

## 上游职责边界

`start_policy.supported` 表示 QCopilots 的执行与发布策略支持，不代表算法依赖齐全，也不保证某个输入一定能成功处理。

Native Processing、GRASS provider 和其他上游组件的算法参数、可用依赖、会话状态及计算契约由对应组件维护。QCopilots 保留其错误并管理本作业输出，不维护按算法名称编写的依赖黑名单、参数改写、MASK 清理或替代算法。上游更新后可直接复测接入结果。
